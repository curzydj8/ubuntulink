# UbuntuLink 安全设计（阶段 0，2026-10-11）

> 安全设计前置，不在最后补。本文件随各阶段实现更新。

## 1. 配对与身份

- 配对必须由用户在 Ubuntu 端明确授权（二维码/短时配对码）。
- 配对码：有效期短（如 5 分钟）、限制尝试次数（如 5 次）、失败冷却。
- 每台设备拥有唯一设备 ID + 非对称身份密钥；身份可识别、可撤销。
- 长期密钥：Android 端进 Keystore；Ubuntu 端文件权限 0600，仅属主可读。

## 2. 会话与通信

- 桌面观看会话必须认证 + 加密（能看到桌面即能看到敏感内容）。
  Tailscale 路径依赖 WireGuard 加密；LAN 直连必须使用 WSS
  （自签证书在配对时交换指纹确认）。
- 监控数据接口与桌面观看接口统一走配对认证；无"游客模式"。
- 观看会话在 Ubuntu 端有可见活动状态（通知/指示器，阶段 4 实现）。
- 网络断开（心跳超时）→ 立即冻结/结束观看会话。

## 3. 最小权限

- Agent 默认以普通用户运行，永不默认 root。
- 监控走只读系统接口；桌面捕获走 portal 系统授权弹框。
- **不实现任何输入注入与命令执行，从架构上消除远程操作面。**

## 4. 滥用防护

- 配对暴力尝试限制；超大消息/频繁连接限流。
- 普通日志不输出密码、令牌、私钥、完整敏感数据。
- 用户可在 Ubuntu 端查看已授权设备并一键撤销；撤销立即生效。

## 5. 第三方组件与许可证

- 远程桌面选型（portal/GNOME Remote Desktop/其他）在阶段 4 记录许可证
  及分发要求；`THIRD-PARTY-LICENSES.md` 在引入时更新。
- 不引入隐蔽远程控制、开机隐蔽接管、绕过系统授权的功能。

## 6. 数据与隐私

- 服务端（未来）只做注册/信令/协调，最小化存储；敏感凭据受保护；
  用户数据的存储与删除规则在服务端设计时明确。
- 本地历史记录仅存非敏感条目。
